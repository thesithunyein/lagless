Lagless documentation

Overview

Lagless is a Uniswap v4 hook. It raises your pool's fee on Unichain about two seconds after the same pair moves on Base, and lowers it again when prices match. The trade that closes the gap pays your LPs more.

Fully on-chainNo bots, keepers or off-chain servers. Reactive Network runs the logic.
BoundedThe fee is capped at 1% and every raise expires on its own.
Drop-inOne hook on a dynamic-fee v4 pool. Nothing for LPs to manage.

The problem

The same pair trades on Base and Unichain. When the price moves on Base first, the Unichain pool keeps quoting the old price until someone arbitrages it. That gap is profit for the arbitrageur, and LPs pay for it (loss-versus-rebalancing).

How it works

  1. WatchA swap on the Base pool emits Swap with the new sqrtPriceX96.
  2. DecideLaglessReactive.react() on Reactive Omni compares both prices. If the gap is 20 bps or more, it picks a fee and requests a callback.
  3. ProtectLaglessHook.setShield() raises the fee for 10 seconds. beforeSwap returns it to the PoolManager with the override flag.
  4. ResetWhen the Unichain price catches up (gap of 5 bps or less), the reactive contract calls clearShield() and the fee drops back to 0.30%.

Fee formula: fee = min(maxFee, baseFee + slope × gapBps). With the default settings, a 40 bps move raises the fee from 0.30% to 0.50%.

Limitation. In 10 race rounds, arbitrage sent the moment the Base swap confirmed landed 1–2 blocks after the fee rose. A faster bot, for example one reading Base pre-confirmations, can still trade inside the ~2 second window and pay the base fee. Lagless shortens the free window. It does not block arbitrage.

Quick start

You need Foundry and Git.

git clone https://github.com/thesithunyein/lagless
cd lagless
forge install
forge test -vv

19 tests cover the fee curve, caps, expiry, rejection of unauthorized callers, the one-time reactive binding, a fuzz test on the fee cap, and a full local loop from a Base move to a cleared fee.

Deploy a pool

Everything runs on testnets at no cost. Use a wallet you only use for development, funded on Base Sepolia, Unichain Sepolia and Reactive Lasna (lREACT).

Keep keys local. Store the key in a Foundry keystore or a git-ignored .env. Never paste it into chats, issues or pull requests.
cp .env.example .env    # fill in RPC URLs and your dev key
source .env

  1. Deploy tokens on both chains

    CREATE2 gives them the same address on Base and Unichain. Set TOKEN_A and TOKEN_B from the output.

    forge script script/Deploy.s.sol:DeployTokens --rpc-url $BASE_SEPOLIA_RPC --private-key $PRIVATE_KEY --broadcast
forge script script/Deploy.s.sol:DeployTokens --rpc-url $UNICHAIN_SEPOLIA_RPC --private-key $PRIVATE_KEY --broadcast

  2. Create the source pool on Base

    Set BASE_POOL_ID.

    forge script script/Deploy.s.sol:DeployBasePool --rpc-url $BASE_SEPOLIA_RPC --private-key $PRIVATE_KEY --broadcast

  3. Deploy the hook and pools on Unichain

    Mines a hook address with the right permission bits, then creates the Lagless pool and a static 0.30% control pool. Set HOOK, LAGLESS_POOL_ID and CONTROL_POOL_ID.

    forge script script/Deploy.s.sol:DeployUnichain --rpc-url $UNICHAIN_SEPOLIA_RPC --private-key $PRIVATE_KEY --broadcast

  4. Deploy the reactive contract

    Subscribes to both pools and prepays 0.1 lREACT into its Omni reserves. Set REACTIVE.

    forge script script/Deploy.s.sol:DeployReactive --rpc-url $LASNA_RPC --private-key $PRIVATE_KEY --broadcast

  5. Bind the hook

    A one-time call. After this, only your reactive contract can change the fee.

    forge script script/Deploy.s.sol:SetReactive --rpc-url $UNICHAIN_SEPOLIA_RPC --private-key $PRIVATE_KEY --broadcast

Run live rounds

script/rounds.py moves the Base price, waits for the fee change on Unichain, then sends the same arbitrage trade to the Lagless pool and the control pool. Each round adds a row to results.csv.

python3 script/rounds.py --sync 150   # once: align Unichain with the Base price
python3 script/rounds.py 20           # 20 rounds, alternating direction
python3 script/rounds.py 10 --race    # arbitrage fires right after the Base move

It signs with the Foundry keystore account lagless and asks for the password once. Latest results are on the home page, read live from the chain.

Security model

  • Only the Unichain callback proxy can raise or clear a fee, and only with a payload that Reactive Omni stamped with your reactive contract's address.
  • The reactive address is bound once and can never change.
  • The fee is always between the base fee and the cap, and every raise expires by timestamp, so a stuck signal can't freeze the pool.
  • No other admin functions. No upgrade path.

Troubleshooting

Subscriptions show INACTIVE on Reactscan

The reactive contract has debt on the Omni ledger. Top up its reserves; depositTo settles the debt first.

cast send 0x8888888888888888888888888888888888888888 "depositTo(address)" $REACTIVE --value 0.1ether --rpc-url $LASNA_RPC --private-key $PRIVATE_KEY

Depositing to the legacy 0x…fffFfF service or calling coverDebt() does not clear Omni debt.

Transactions on Lasna stay pending

Lasna has a 100 gwei minimum base fee and needs a priority tip. Add --with-gas-price 101gwei --priority-gas-price 1gwei.

Pool creation reverts

The hook only accepts dynamic-fee pools. Create the pool with the fee set to 0x800000.
